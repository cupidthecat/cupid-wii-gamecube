# CPU execution

The interpreter executes guest PowerPC instructions against the physical bus. CPU state holds 32 integer registers, two binary64 lanes per floating register, condition and floating status registers, segment registers, special registers, and cycle counters. It owns instruction and data relocation. The runtime can inspect the last obtained instruction word through `last_pc` and `last_opcode` without performing another guest memory access. `last_step_fetched_instruction()` tells whether the latest attempt obtained a word; interrupts and fetch failures retain the earlier fields. An obtained zero, a decoded guest exception and unfinished decoded execution all report true. This includes zero fetched at an odd PC and data-alignment faults from decoded instructions. Reset, translation rejection, and errors before a word is available report false. This diagnostic flag is separate from architectural `State`.

The behavioral reference is pinned at `562875dd60fd0ff50b65dbbb611a2096802cd1b9`. These paths are relative to that checkout. The implementation is written for this project's bus and state interfaces.

## Compatibility decisions

BATs accept either validity bit and do not enforce block protection, matching the behavioral reference's current treatment. Hashed pages likewise do not enforce segment keys or page protection. The guest still receives instruction and data storage exceptions for missing translations, and instruction fetch rejects a segment's no-execute flag on a TLB miss.

BAT matching also follows the entries produced by the pinned table updater for noncontiguous block masks and overlapping effective-base fields. Effective-base bits set within the block mask remain fixed in the incoming address; physical translation retains the OR of its block bits and the physical base. Higher numbered mappings take precedence. The extended bank is enabled only on Wii when HID4 SBE is set. Invalid BAT configurations here follow the observed software table output; no physical-console behavior is claimed.

Instruction and data BAT lookups each use a lazily allocated 128 KiB host table. Every relocated access compares all raw upper and lower registers in the active bank against its snapshot. A register change or a change between four and eight active BATs rebuilds the table before lookup, including direct edits through `state()`. x86-64 uses exact SSE2 comparisons of the snapshots; other hosts use byte comparison. Rebuilding enumerates the block mask in ascending bank order, retaining malformed mappings, W/I attributes and overlap priority. The tables add two host pointers to the interpreter and do not change architectural state, bus transactions or page-table lookup order.

The mutable-BAT fixture keeps its reference memory manager on the heap with ordinary `std::unique_ptr` ownership. Native MSVC Release with LTO initially failed with Windows stack-overflow status `c00000fd`: the minimized fixture reserved 1,063,856 bytes in one compiled frame against the executable's unchanged 1,048,576-byte stack reserve. The debugger stopped in the stack probe before comparisons began. Moving only the 524,720-byte reference memory-manager object to the heap reduced that frame to 539,152 bytes and retained all 131,072 cases and their assertions. The timeout and executable stack settings remain unchanged. The original failure, debugger output, unwind records and correction are retained in `.cache/cpu-bat-simd-20261004/native-memory-debug/debugger-receipt.json`.

Single loads preserve NaN payloads and signaling bits. Single stores use the guest's bit transfer rules rather than a host rounding cast. Quantized integer transfers apply the six-bit signed scale, clamp to their integer range, and truncate. Single scalar results fill both register lanes; binary64 operations preserve the second lane.

`addme` and `subfme` follow the pinned caller's carry formula. An incoming carry of one clears outgoing CA. With incoming carry clear, `addme` sets CA when its source operand is nonzero; `subfme` sets it when its source operand differs from `ffffffff`. Register results wrap to 32 bits. OE controls OV replacement and sticky SO, and Rc classifies the result using the updated SO. These choices follow the compiled instruction handlers; no physical-console carry measurement is claimed.

A conditional store that raises a guest data storage exception clears CR0 LT, GT and EQ, retains XER SO in CR0, and preserves the reservation. A guest handler can repair the translation and retry the same store after `rfi`. Alignment rejection precedes reservation checking and preserves CR0. An unfinished host device operation fails explicitly without changing CR0 or consuming the reservation. This follows `stwcxd` in `Interpreter_LoadStore.cpp` and the distinction between guest DSI and unfinished bus operations.

External-control word transfers require EAR's enable bit before checking alignment or translation. EAR rejection sets DAR and enters the data storage vector while retaining DSISR and the source or destination register. Enabled misaligned transfers enter the alignment vector. An enabled read that reaches a guest storage fault assigns zero to its destination, following the behavioral caller's unconditional assignment of the failed read result. These instructions are permitted in user mode and do not require floating-point availability. Unfinished bus operations retain the destination and fail explicitly without entering a guest storage exception.

Both cache-zero forms translate the aligned cache line once and write eight physical words. String stores also use aligned word writes, reading and retaining surrounding bytes when the first or last word is partial. Prefix and suffix reads remain separate, including when they refer to the same word. A misaligned indexed string store with a zero byte count still performs those two reads and the merged word write, following `Helper_StoreString`. Guest storage faults stop the remaining string or cache-zero transfers while retaining writes that already completed. An unfinished device operation preserves CPU exception state and execution counters, without fabricating a guest storage fault.

BAT translations carry the write-through and cache-inhibited attributes into physical transactions. For affected RAM writes shorter than a word or starting at a non-word boundary, the CPU rotates the full incoming 32-bit value and duplicates it into both words of each covered eight-byte region. It requests the PI memory-access interrupt before those writes. FIFO, EFB, MMIO and valid locked-cache addresses follow their earlier physical-region rules instead. Halfword byte-reversed stores retain the incoming upper halfword while swapping the lower halfword, which matters for this duplication.

Hashed-page and TLB results use normal physical writes even when their PTE contains W/I. The inspected inner page helper computes W/I and the TLB retains those attribute bits, but both successful page-result constructors omit the flag, whose default is false. The outer translation caller returns that result unchanged. This implementation follows that observable caller output while preserving R/C updates, C-bit reparsing, cached physical addresses and invalidation. BAT results explicitly include W/I and keep the duplication and PI request behavior above. This distinction is verified against the compiled callers; it is not a claim about physical-console behavior.

Page-crossing writes split before translating each half. Binary64 stores issue two ordered word transfers, each with its own translation. A guest fault in the first half still permits the second transfer under the original relocation state. If the second succeeds, the first fault is delivered; if both fault, the second address remains in DAR. Reference/change bits and successful writes from the second transfer remain observable. Unsupported device operations and host failures stop immediately. Binary64 EFB writes retain their explicit unsupported diagnostic.

Quantized float-pair stores can start at arbitrary alignment. Each of their word transfers therefore passes through the page splitter too, including nested splits across noncontiguous physical pages. Their page translations use the same normal-write result and preserve the same deferred guest-fault ordering.

Page-crossing reads split into ordered byte transfers before any translation. Each byte uses the instruction's original relocation state, including after an earlier byte raises a guest storage fault. The last failed byte supplies DAR; successful later reads still set the mapped page's reference bit. Integer, binary64 and quantized load destinations and update registers remain unchanged when any byte faults. Unfinished bus operations and host failures stop the remaining reads immediately and retain their distinct diagnostics. This follows `ReadFromHardware` and the load callers' checks before assigning register results.

Writing a nonnegative decrementer starts a separate twelve-cycle phase at the write. Expiry follows the reference event deadline of the written value multiplied by twelve; a zero write expires at the current instruction boundary. Expiry sets the register to `ffffffff` and requests an interrupt. Negative values remain fixed. A positive-to-negative write also requests an interrupt and cancels the countdown. A later write replaces the deadline without clearing an already pending interrupt. Delivery waits for MSR EE, preserves the interrupted PC and MSR in SRR0/SRR1, and gives an external interrupt priority over a pending decrementer interrupt.

Writing either writable timebase half restarts the timebase's twelve-cycle phase at that instruction. The other half is preserved, and subsequent low-half carry and full-width rollover follow modulo-64-bit arithmetic. Reads through `mftb` or `mfspr` sample the value before the reading instruction advances cycles and are permitted in user mode. Rejected privileged or read-only writes preserve the existing phase. The timebase and decrementer phases are independent: writing either clock does not move the other clock's next tick or interrupt deadline. This follows `TimeBaseSet` and `GetFakeTimeBase` in `Source/Core/Core/HW/SystemTimers.cpp`, their writable-half callers in `Interpreter_SystemRegisters.cpp`, and reset in `PowerPC.cpp`.

`mtmsr` checks an enabled floating exception after applying the new MSR. Synchronous floating delivery saves the current instruction address; an already pending external, monitor or decrementer interrupt exposed by EE saves the following instruction address. Privilege rejection precedes both checks. Floating arithmetic and FPSCR writes check delivery when they update the exception summary. A sticky FEX bit alone does not repeatedly trap on register moves, finite arithmetic or a repaired operation retried after `rfi`. A newly signaled condition still requests delivery when its sticky bit was already set. These details follow `CheckFPExceptions`, `UpdateFPExceptionSummary`, `SetFPException`, `mtmsr` and their instruction callers.

XER writes retain SO, OV, CA, the eight-bit byte-compare field and the seven-bit byte count; reserved bits read as zero. Quantization register spare bits retain guest writes. Invalid `mftb` selectors are explicitly unsupported, matching the behavioral caller's restriction to the two readable timebase halves without inventing a successful register read or guest exception.

The four performance counters support selector zero (no increment) and selector one (instruction cycles). PMC2 also supports selector eleven for decoded load/store instructions, and PMC3 supports selector eleven for decoded floating instructions. The classification includes cache-block operations, indexed and quantized transfers, and floating system instructions. A multiword or paired instruction contributes one event. A decoded instruction that enters a synchronous guest exception still contributes its metadata events, matching the target interpreter; an instruction-fetch fault contributes none. Counter writes are followed by the writing instruction's own increment. Reads through UPMC1 through UPMC4 update the alias from PMC1 through PMC4, with the same privilege check as the behavioral caller. Unsupported event selectors fail before the control register changes.

The monitor interrupt is requested when an enabled counter's sign bit is set after an instruction. PMC1 uses its individual interrupt-control bit; the other counters use the shared control bit. Pending requests survive later counter or control-register writes and wait for MSR EE. Delivery uses vector `f00` and has priority after the external interrupt and before the decrementer. The handler must resolve a still-active counter condition to avoid another request after it executes an instruction. Additional monitor freeze, threshold and transition controls do not affect the pinned update routine and are not independently modeled as hardware features.

The instruction cache has 128 sets, eight ways per set, 32-byte lines and tree replacement. Disabling the cache bypasses its contents. Locking it retains existing lines and prevents allocation on a miss. `icbi` invalidates all ways of the indexed set, including while the cache is locked or disabled, and HID0's instruction flush bit resets the cache before clearing itself. Data accesses currently use coherent backing memory; dirty data lines remain unfinished. [Locked-cache DMA](locked-cache-dma.md) transfers use the existing physical cache storage, with immediate completion following the target software caller. Guest illegal and privileged instructions enter the program exception vector; valid instructions with unfinished behavior throw a diagnostic containing the instruction and PC. Unfinished device operations also fail explicitly instead of entering a guest storage exception.

Instruction-cache lookup uses a 4,096-entry host hint table. Every hint checks the guest line's full tag and validity before use; colliding hints fall back to the eight-way lookup. Eviction, invalidation, failed backing fills and reset retain their existing guest behavior. Replacement updates and victim selection use constant tables generated from the same tree traversal. Consecutive accesses to the last validated line reuse its way and skip an idempotent replacement update; reset and invalidation prevent stale reuse. These host hints add no guest storage and never read backing memory on a validated hit.

Cache lookup uses the allocated mask within each physical category. Bit `20000000` selects the virtual category first; otherwise bit `10000000` selects MEM2, and other addresses select MEM1. The default masks are `01ffffff` for MEM1 and the virtual category, and `03ffffff` for MEM2. Keeping the virtual category distinct provides no additional backing storage. An already cached RAM line can therefore serve a physical alias whose cold backing copy would be rejected. Cache misses retain the original physical address for backing reads. Other bus implementations keep their existing physical identity unless they override the cache-key method.

Instruction backing copies use only real MEM1 and MEM2 spans, including their top-two-bit aliases. They exclude device callbacks, allocated padding, CPU data mirrors and locked-cache backing. A rejected copy retains every destination word and increments `instruction_backing_read_errors`, without requesting PI or a storage exception. With caching disabled, the initialized word therefore remains zero. An unlocked cache miss retains the selected way's existing eight words when its backing copy fails, then installs the new tag and updates replacement state. Invalidation and reset discard validity while retaining those words. A subsequent locked hit can read the installed line. Invalid locked misses fail explicitly because the behavioral caller's destination word is uninitialized on that path; no value is invented. Generic buses keep their ordinary word-read fault behavior.

A fetched zero word advances PC by four and returns zero cycles without dispatching an instruction. With no pending exception, it preserves the guest registers and performance counters and creates no program exception. The last fetched PC and opcode are still recorded. Successful-execution `instructions`, CPU cycles, timebase and decrementer phase do not advance. Other reserved instruction words retain their program-exception behavior. This follows the inspected zero-word branch and its metadata; it does not assign hardware semantics to that word.

Failed instruction translation enters the ISI vector at `400`, saves the faulting address in SRR0 and sets the page-fault cause in SRR1. It retains DAR, DSISR and successful-execution counters and contributes zero cycles. The inspected `Read_Opcode` returns zero after requesting ISI, and the interpreter then uses zero-cycle metadata while delivering the exception. The ISI comparisons use aligned instruction addresses.

Instruction fetch accepts byte-addressed PCs, following the inspected caller rather than introducing a separate alignment exception. With caching disabled, it reads four consecutive backing bytes. Cached reads assemble those bytes from one or two 32-byte lines without rounding the starting address down to a word. Each missing unlocked line requests its full backing line; a missing locked line requests only its part of the instruction and remains unallocated. A split fetch can therefore combine stale cached bytes with fresh backing bytes. Every copy remains within the selected line's byte storage. The bounded byte backing API accepts one through 32 bytes, retains the whole destination on failure, and uses the same strict RAM bounds and diagnostic counter as word backing. Its generic-bus default stages the copy before assigning the destination. These are software-caller compatibility decisions; no physical-console behavior for odd instruction PCs is claimed.

CPU MEM1 data transfers use 32 MiB of allocated backing, including padding beyond the real 24 MiB size. Physical addresses below `08000000` mirror through the allocation mask. Host spans, fetch backing and RAM DMA remain bounded by the real size, with only the top two address bits stripped for host aliases. MEM2 data access requires its real region, and high physical addresses do not acquire CPU RAM aliases. An unresolved CPU data read requests PI and returns zero; an unresolved store requests PI and discards its value. These physical failures retain DAR and DSISR and do not become translation exceptions. Unfinished device operations retain their separate failure path.

Page-table reads use CPU data backing, while R/C writes use the strict host span. A table in allocated padding can therefore translate successfully without retaining its R/C bits in backing RAM. The local TLB still retains its updates. Rejected R/C writes return a failure indication that the CPU ignores, increment `page_table_write_errors`, and leave RAM, PI and guest exception state unchanged. These distinctions follow the complete memory callers at the pinned revision; they are not physical-console measurements.

Reciprocal segments come from sampled outputs at the pinned reference's segment boundaries. The sampler called the actual reference functions and measured output fraction and slope. The runtime reconstructs the estimates with its own exponent handling and interpolation. Single fused arithmetic computes a host binary64 FMA, then resolves binary32 halfway cases by comparing an exact integer product and addend with the rounded result. Floating arithmetic applies the guest rounding mode within a scope and restores the host's previous mode afterward.

NI preserves subnormal inputs and flushes tiny outputs to signed zero. Binary64 tininess follows significand rounding with an unrestricted exponent, before rounding into the subnormal range. This distinction matters when the final binary64 result would be the smallest normal number: multiplying that number by the value immediately below one still flushes, while a fused result closer to the normal boundary can remain normal. The runtime resolves this rare boundary with exact integer products, sums and quotient comparisons. It does not depend on host FTZ or DAZ settings. Single output conversion separately flushes values below the binary32 normal threshold before conversion rounding, matching `ForceSingle`.

## Validation

The cache lookup optimization passed 393,216 chained cache reads against the unchanged compiled `PPCCache.cpp`, split equally between GameCube and Wii. The sequences exercise colliding guest tags and host hint slots, repeated line hits, top-bit physical aliases, changed backing bytes, every byte offset, disabled and locked accesses, set invalidation and reset. Output words and ordered backing copies match exactly on Linux GCC. Existing odd-PC, retained failed-fill, integer, branch and carry comparisons also pass. A separate local comparison against the preserved pre-optimization runtime matches all public CPU-state fields, each ordered bus operation and both final authored RAM images across 8,192 steps. The two binary records match byte for byte (78,976,832 bytes). These checks establish bounded equivalence for the changed cache path; they do not establish commercial-game full speed.

On an Intel Core i9-10900F with GCC 13 Release under WSL2, five alternating 100-million-step Sunshine runs took median elapsed times of 6.431 seconds before the cache change and 6.003 seconds after it. One three-billion-step pair took 211.680 and 185.991 seconds respectively, a 12.1% reduction in elapsed time. The longer pair produced identical emitted final JSON, including 320 presented frames, 65,917 graphics commands, 18,956,440 fragments and frame/audio hashes. Both variants used the same frozen source outside the CPU cache, headless software graphics, a fixed input replay, validated IPL fonts and isolated persistent data. Two native game observers continued running during timing; one focused reference check also ran during the longer baseline. These measurements include startup and persistence, and support only this bounded workload comparison. The emitted commercial-game JSON did not expose every CPU register; complete-state equality was checked separately with the authored sequences above.

`tests/cpu_tests.cpp` uses newly authored synthetic opcodes and expected states. It checks integer boundary cases, 1,000 arithmetic pairs and their carry bits, conditional branch and link behavior, update loads on a fault, reservation stores, multiple transfers, exceptions, interrupts, decrementer ticks, performance counters and aliases, BATs, primary page translation, TLB caching and invalidation, NaN transfers, scalar arithmetic and conversions, paired arithmetic, quantized transfers, all four rounding modes, cache replacement, self-modifying instruction visibility, cache locking and invalidation. An authored cache-range loop verifies line-count rotation, CTR assignment and decrementing branches, including 64 MiB and 2 GiB length calculations and an exact twelve-instruction three-line run. ## Reusing host rounding controls

Scalar, paired-single and quantized operations use the guest FPSCR rounding
mode. The host guard changes that mode only when the incoming controls differ.
On x86-64 it checks both the C floating-point mode and the SIMD rounding bits.
An operation that changes the controls restores the saved C mode when it exits,
including guest faults and rejected quantization. Host C libraries can report
split scalar/SIMD controls differently; the checks retain each library's saved
mode behavior.

The public fixture checks 448 scalar, paired, fault and split-control cases on
x86-64 across both consoles and all four host and guest rounding modes. A
separate frozen before/current trace matches 16,384 complete CPU states, ordered
bus records, final RAM, host rounding controls and host exception flags byte for
byte. [Performance measurements](performance.md) record the authored floating
workload separately from commercial gameplay.

## Unfinished behavior

Little-endian execution, direct-store segments, NaN-to-integer quantization, locked-cache DMA queue timing, additional performance event selectors, and data cache visibility remain unfinished. Those recognized unfinished execution paths report explicit diagnostics. The timebase uses a twelve-cycle divider and the decrementer uses its own write phase. Full device scheduling and edge timing still need differential validation.

PI memory-access error address and cause registers remain unmodeled beyond the interrupt request, matching the pinned caller's stated gap. Full MMIO transaction-width and fault fidelity still needs validation outside the tested store paths.
