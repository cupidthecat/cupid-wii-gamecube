# Primitive assembly and rasterization

`Rasterizer` accepts BP/XF state and transformed vertices. Its fragment callback receives EFB coordinates, 24-bit depth, interpolated colors, projected texture coordinates and derivatives. The caller owns shading, alpha/depth tests and blending. Keep the rasterizer alive across commands: its remembered depth plane implements zfreeze. `reset` restores the initial plane.

The behavioral reference is pinned at `562875dd60fd0ff50b65dbbb611a2096802cd1b9`. Paths below are relative to that checkout. The implementation uses this project's vertex and fragment interfaces.

| Behavior | Reference implementation and callers | Local implementation |
| --- | --- | --- |
| Skipped vertices and compacted primitive inputs | `Source/Core/VideoCommon/VertexLoader.cpp`: `SkipVertex`; `VertexLoaderManager.cpp`: `RunVertices`, `AddIndices(num_loaded)` | `draw` |
| Quads, trailing triangle, lists, strips and fans | `Source/Core/VideoCommon/IndexGenerator.cpp`: primitive index generators; `VideoBackends/Software/SetupUnit.cpp` | `draw` |
| Homogeneous clipping, culling, interpolated clipping colors | `Source/Core/VideoBackends/Software/Clipper.cpp`: `CalcClipMask`, `ClipTriangle`, `ProcessTriangle`; `NativeVertexFormat.h`: `Lerp` | `triangle`, `interpolate` |
| Line and point expansion, texture offsets | `Source/Core/VideoBackends/Software/Clipper.cpp`: `ClipLine`, `ProcessLine`, `ProcessPoint` | `line`, `point` |
| Wrapped scissor ranges and draw order | `Source/Core/VideoCommon/BPFunctions.cpp`: `ComputeScissorRanges`, `ScissorResult` | `scissors` |
| Fixed coverage, slope sampling, zfreeze and 2×2 texture derivatives | `Source/Core/VideoBackends/Software/Rasterizer.cpp`: `DrawTriangleFrontFace`, `Slope`, `BuildBlock`, `UpdateZSlope` | `rasterize`, `update_depth`, `Plane` |

Skipped indexed vertices are removed before assembly; they do not restart strips. Quads accept a trailing set of three vertices as a triangle. Triangle clipping follows the reference CPU path, including its positive-Z mask and W-plane compatibility behavior. Disabling clipping allows an unclipped polygon when all clip W values are nonnegative. Points follow the reference's expansion without homogeneous clipping. Zero W and non-finite coordinates raise explicit errors where division or integer conversion would be undefined.

Coverage rounds to 28.4 coordinates, applies the reference's minus-nine adjustment, and uses its edge inclusion rule. Attribute slopes use the 0.495 sample offset. Colors interpolate affinely and truncate after clamping. Texture coordinates receive BP scales before clipping, then interpolate as STQ divided by clip W. Derivatives are differences from the same aligned 2×2 block for every covered pixel in that block. Lines use horizontal or vertical caps according to their dominant axis; line/point widths and optional texture offsets come from BP state.

Scissor rectangles can wrap in both axes. Each valid wrapped region is rendered in the reference's viewport-area order. The depth plane updates even when culling or scissoring rejects a primitive, and it remains unchanged after trivial clip rejection or a zero-area primitive. The zero-area guard avoids a non-finite slope followed by undefined float-to-integer conversion in the reference CPU path. This is a defined local behavior, not a claim that an undefined host result reflects console behavior.

Depth-plane origins use the defined signed conversion range separately from coverage coordinates. Culled triangles can project far outside the EFB and still update the plane used by a later zfreeze draw. Applying the edge-product range limit to those origins previously raised a raster-coordinate error. The public regression draws culled triangles with positive and negative eight-million-pixel X/Y origins, then checks all seven remembered plane fields through a later frozen draw. The baseline fails with that error; the corrected path passes Windows GCC and MSVC, and Linux GCC with address, undefined-behavior and float-cast-overflow sanitizers. Coverage coordinates retain their edge-arithmetic check.

Origins whose scaled intermediate exceeds signed 32-bit range now use a signed
64-bit intermediate. The original conversion and rounding remain unchanged
within their prior range. Binary32 values outside that range are integral;
after the original shift, the final anchor must still fit signed 32-bit storage
and allow subtraction from every EFB pixel without overflow. Non-finite inputs,
unsafe final anchors and coverage coordinates retain explicit range errors.
Authored public tests check both axes and signs, nonconstant frozen depth,
literal boundary anchors and independent signed 64-bit pixel deltas. A private
captured triangle also passes the normal draw API and retained-plane checks
under MSVC, GCC and Clang ASan/UBSan. Game execution past its original failure
point remains to be verified.

The actual-source comparison also checks 144 wide culled/frozen command pairs across both axes and signs, origin distances of 5, 8, 64 and 128 million pixels, W values of 0.5, 1 and 2, and three scissor offsets. Windows MSVC and Linux GCC each pass 82,221 emitted sample comparisons across these pairs and the existing 10,000-command corpus.

The native Sunshine opening-transition failure was captured at field 6,717 and instruction 54,146,047,965. The diagnostic run matches every final state field, the last frame, all 24 MiB of main RAM and the PCM bytes from the earlier failed run. Its thirteen-vertex triangle strip reaches the error on primitive ten: the projected X origin is 4,552,191 pixels, or 72,835,056 in the coverage conversion, just beyond the coverage-only range. The actual source processes eleven triangles: eight are trivially rejected and three are culled. They emit no samples, but the culled triangles must update the remembered depth plane.

An exact-error reduction retains four vertices and ten load-bearing nonzero input words. The first degenerate triangle preserves strip parity before the wide culled triangle. Removing any retained word or vertex loses the original error and failing coordinate bits. Both the complete command and this reduction fail before the fix and finish after it, with every final depth-plane word equal to the actual source. The same commands pass Linux undefined-behavior and float-cast-overflow checks. Only unused backend vptr metadata is excluded from the isolated test collector; the product and unchanged raster implementation retain their arithmetic checks. Private commands, captures, source/binary hashes and before/after results remain in `local-artifacts/raster-worker-20261004/guest-captured-replay-verification.json`.

The public strip regression uses the reduced positions and normal draw callbacks. A later zfreeze draw exposes all seven remembered plane fields, including negative-zero slopes and the exact X/Y origins of 4,552,191 and -342. The baseline raises the original coordinate error; Windows GCC, MSVC strict Release and Linux GCC with address, undefined-behavior and float-cast-overflow sanitizers pass after the fix. A separate ordinary-input continuation uses the original frozen core with a layout-preserving depth-origin repair, an identical copied storage seed and replay, and OpenGL. Its early retained checkpoints match every reported state field, frame byte and SI-read prefix. Execution beyond field 6,717 and controllable level gameplay remain to be verified separately.

The rasterizer caches the ordered scissor rectangles between draw commands. It checks the BP top-left, bottom-right and offset words and the XF viewport width, height and X/Y origins before each draw. Changing any of those words rebuilds the rectangles; changing depth or other shading state does not. Cached empty regions still follow the same depth-plane update rules. The public test compares retained and fresh rasterizers after each relevant state change, including wrapped submission order and transitions to and from an empty region. Removing any one of the seven cache inputs makes this test fail.

Triangles inside every clip plane, or using the permitted clipping bypass, project directly into rasterization after culling. They do not allocate a temporary clipping polygon. Triangles that cross clip planes use the same ordered clipping and interpolation path.

The compacted, texture-scaled vertex buffer retains capacity across draw commands. Each draw clears its elements before loading the new input, so skipped vertices and smaller following commands retain their ordinary assembly behavior. Nine alternating MSVC Release runs of the same one-million-triangle setup workload measured medians of 0.303170 seconds with a fresh buffer per command and 0.232932 seconds with retained capacity. All runs produced checksum `508000000`; the public tests and actual-source sample comparison pass after the change. These timings measure CPU setup on a host running other work and establish no commercial game speed.

An isolated MSVC Release setup benchmark submitted one million identical triangles through the hardware callback. Five alternating runs measured medians of 1.222 seconds for uncached setup, 0.604 seconds with the scissor cache, and 0.526 seconds with the cache and direct projection. Every run produced the same command checksum. The host also ran other builds and a game capture. These timings measure CPU triangle setup; they do not establish a game frame rate. The full actual-source raster comparison passed on Windows MSVC and Linux GCC after both changes, with 81,357 emitted sample comparisons over 10,000 commands on each platform. Linux address and undefined-behavior sanitizer checks also passed the public raster tests.

`tests/rasterizer_tests.cpp` passed native Windows GCC with warnings treated as errors and Linux GCC with address and undefined-behavior sanitizers. It checks exact small-triangle and quad coverage, single shared-edge writes, compacted skipped input, strip/fan assembly, color/depth slopes, projected STQ, BP scales, 2×2 derivatives, scissor rejection/wrapping, clipping, zfreeze persistence and reset, line/point coverage and texture offsets. Multisample coverage remains unfinished and raises an explicit error.

`tests/rasterizer_reference_checks.cpp` links the actual pinned `Clipper.cpp`, `Rasterizer.cpp` and `BPFunctions.cpp`, with a test collector replacing downstream shading. Its generated triangle, line and point corpus compares coordinates, depth, both color channels and eight texture inputs at their s17.7 transfer boundary. It varies clipping, culling, scissoring, W, vertex coordinates, BP texture scales, line/point sizes and texture offsets, and frozen depth. Each case starts from reset state; frozen cases first seed a defined depth plane. This avoids carrying the reference's undefined zero-area slope result into later cases. No failed case is counted as a successful comparison.

The optional harness requires the external `Source/Core/` include directory, C++23, fmt and strict floating options. Test-only backend hooks fail if unrelated application entry points retained by a linker are called. Function-section garbage collection can discard those unused paths. It does not vendor reference files. These checks cover the reference CPU path; real hardware rasterization has not been validated.
