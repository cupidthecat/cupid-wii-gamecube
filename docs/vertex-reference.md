# Vertex decoding and transforms

`VertexDecoder` reads CP register state, XF memory, vertex command bytes and physical vertex arrays. The caller selects one of the eight VAT entries, obtains the input byte count, then decodes each vertex. The decoder returns position, normal/tangent/binormal, two RGBA colors, eight texture coordinates and position/texture matrix indexes. A maximal indexed position value marks a skipped vertex and avoids reading its arrays. Missing positions, incomplete input, invalid array addresses and reserved color formats raise errors.

The behavioral reference is pinned at `562875dd60fd0ff50b65dbbb611a2096802cd1b9`. Paths below are relative to that checkout. The implementation is written for this project's memory and command state interfaces.

Transforms return model coordinates and homogeneous clip coordinates. Primitive assembly and clipping belong to the caller. Viewport division is a separate operation so clipping can occur first. Its output includes the raw XF viewport origins; the rasterizer applies the EFB origin and scissor convention. Perspective depth uses the reference transform unit's small scale adjustment.

Integer positions and texture inputs use the VAT fraction when ByteDequant is enabled, matching the reference's native loader call path. Formats 4 through 7 transfer binary32 values. Normal inputs use their format's fixed fraction independently. Color outputs use RGBA order; register material colors are numeric `0xRRGGBBAA`. Color and alpha can choose different material sources.

Regular texture generation supports geometry, normal, tangent, binormal and all eight input texture rows, AB11/ABC1 inputs, ST/STQ matrices, and dual post transforms with optional normalization. It follows the reference's NaN-input replacement and zero-Q clamp. Color generators read the transformed channel; emboss generators offset an earlier generated coordinate using the selected light and transformed tangent/binormal. Texture outputs have no BP scale applied: the caller multiplies S and T by their BP texture-coordinate scales before sampling.

Lighting supports eight lights, independent RGB/alpha channels and masks, register/vertex material and ambient colors, directional/specular/spot attenuation, diffuse none/sign/clamp, and integer material modulation. It follows the reference CPU transform caller's floating accumulation and final truncation. The inspected shader generator instead rounds each light contribution before accumulation, and its host uniform upload normalizes light directions. Those shader-specific choices are not substituted into this CPU path. A non-finite lighting accumulation raises an explicit error because it has no defined host integer conversion; reserved diffuse and texture generator modes also raise errors.

`tests/vertex_tests.cpp` uses authored command bytes and expected values. It covers 288 position-format/address/fraction/dequantization combinations, all six color encodings in both channels and three address modes, shared/three-index NBT, all eight texture VAT fields and address modes, matrix defaults and masks, model/projection/viewport results, material sources, 48 regular texture generation combinations, dual transforms, color generation, all attenuation/diffuse functions, high light-mask bits, zero denominators, emboss offsets and explicit failures. The standalone suite passed native Windows GCC with warnings treated as errors and Linux GCC with address and undefined-behavior sanitizers. The reference's `Source/UnitTests/VideoCommon/VertexLoaderTest.cpp` was inspected for supported input combinations and skipped attributes; its tests are not claimed as tests of this runtime.

`tests/vertex_reference_checks.cpp` links the actual pinned `Source/Core/VideoBackends/Software/TransformUnit.cpp` and passed 4,800,000 component comparisons across 100,000 generated vertices. It compares model and clip positions, three transformed normals, both color channels and eight generated texture coordinates, using varied matrices, lighting and generators. It requires the external reference's `Source/Core/` headers, C++23, fmt, and strict floating compiler options. Test-only alert/log handlers stop on unexpected diagnostic paths. No reference implementation is vendored. This checks the CPU transform path; it does not establish real hardware accuracy or validate the shader path.
